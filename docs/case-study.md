# Harbor case study

I wanted a repo a reviewer can clone without a private knowledge base, and still see a refusal. The tooling-landscape poster is a trap. One demo per logo does not show whether you can keep a weak source from becoming a claim.

Harbor is a synthetic dual-index corpus. It is not a company wiki and it is not my live notes. I used it so this repository can stay public.

## What I built

A grounded research loop with typed state, labelled retrieval, and a redacted receipt.

LangGraph wraps the same functions as the framework-free pipeline. FastMCP exports `query_knowledge` and `query_projects` only. Review can pause before a receipt. Extractive draft is the default so CI needs no model.

## What I measured

The retrieval shootout compares lexical overlap, a hashed-token vector index, and one-hop `[[wiki]]` expansion on five labelled Harbor questions. The JSON receipt is generated by `grounded-agent shootout`. Tests recompute macro recall and precision from the per-question rows.

n is five. That is the whole experiment. I inspected the misses, including a designed lexical miss that graph expansion is supposed to recover. Do not quote those recalls as an embedding benchmark.

## What I skipped, and how the skill still shows up

I did not use Pinecone, CrewAI, LangSmith, Lakera, or Temporal.

The skills still have a runnable path: a local vector index, an explicit graph with checkpoints, stage traces, fixture injection, and a fail-closed provider switch. Skipping a logo does not skip the skill. Resume language that says "I used X" is only honest when X is in the runnable path.

## The hard part

The hard part was not attaching citations. The hard part was keeping weak-fit nominations out of answers, and keeping a forged tool card from minting `write_index`.

A planted operator alias is copied as `[redacted]`. Receipts and JSONL traces fail if that alias appears. Missing Ollama or hosted credentials exit 2. They do not fall back to extractive.

## What you can infer

You can infer I can write contracts that refuse illegal state, test the refusal, and keep a public receipt free of snippets.

You cannot infer I have run this against a production corpus, a paid model API, or a durable workflow engine. Those claims would need a different receipt.
